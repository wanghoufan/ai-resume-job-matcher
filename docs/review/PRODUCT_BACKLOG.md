## 审查范围与限制（本次）

- 视角：产品经理 / UX / 普通用户 / 高频用户；覆盖功能完整性、易发现性、操作效率、容错、状态反馈、信息架构、一致性、高频操作效率。
- **未覆盖**：视觉 / UI 渲染走查。本环境无浏览器与截图能力，且 `.env.local` 无可交互登录的有效 Supabase 凭据，未能跑通真实端到端体验（登录—生成—编辑—发布—公开访问）。以上结论基于完整阅读 UI 源码（`app/*`、`components/*`）、`PLAN.md` 与 `README.md`，非运行时实测。
- 本次未改动业务代码（超出 Product Reviewer 权限边界）。

## 当前记录

| 编号 | 优化项 | 用户价值 | 优先级 | 状态 |
|---|---|---|---|---|
| PB-001 | 发布成功后显示包含当前生产域名的完整网址，并提供复制链接、打开公开页入口 | 避免用户把相对路径误认为只能本机访问，发布后可直接分享 | P1 | 已采纳（编辑器发布面板已显示 `siteOrigin+publicPath` 完整地址 + 复制/打开；管理列表仍仅显示相对路径，见 PB-003） |
| PB-002 | 产品名称/品牌在各页面不一致：首页顶栏「AI 简历匹配」、`/resume-sites*`「AI 超级求职助手」、`/pricing`「返回求职助手」、README/AGENTS「AI 简历岗位匹配助手」、PAYLOAD 套餐名「AI 简历生成网站」。统一对外称呼 | 招聘方与求职者在不同页面看到不同产品名，认知混乱、降低信任；对外物料（付款台、SEO 标题）也应一致 | P1 | 待评估 |
| PB-003 | `/resume-sites` 管理列表的公开入口只显示相对路径 `/r/{slug}`，无复制按钮 | 用户可能误以为公开页只能本机访问，且无法一键复制去分享（与编辑器发布面板体验不一致） | P2 | 待评估 |
| PB-004 | 岗位匹配流程对「会员额度/状态」不可见，且额度耗尽报错仅文字提示「请升级套餐或下个周期再试」，无跳 `/pricing` 的入口 | 高频用户跑完免费额度后卡住，不知道去哪升级；影响转化与体验 | P2 | 待评估 |
| PB-005 | 发布面板仅后端校验「姓名/职业定位/简介」必填；编辑器中发布按钮在必填为空时仍可点（仅勾选确认后才拦截），失败才返回 422 | 用户填完 slug、勾确认后才发现必填缺失，需回编辑器补，来回成本高 | P2 | 待评估 |
| PB-006 | 首页对已登录用户缺少常驻「我的在线简历」导航，仅 hero 一处链接；两条产品主线信息架构割裂 | 已登录用户分析完想进简历站需“碰运气”找 URL，跨功能效率低 | P2 | 待评估 |
| PB-007 | 通义千问默认模型名不一致：首页为 `qwen3.7-plus`，创建页为 `qwen-plus` | 用户沿用默认名可能触发模型 401/失败，且两处行为不一致 | P3 | 待评估 |
| PB-008 | 分析结果（求职信、优化建议、面试题）无「复制/导出」单块操作，历史记录亦不可复制 | 求职信/建议是高频复用内容，用户只能手动全选复制，高频操作效率低 | P3 | 待评估 |
| PB-009 | `/pricing` 未登录时按钮为「登录后立即付款」，点击后才提示回首页登录，页面内无登录入口 | 想付费的用户被推回首页，多一次跳转；与首页登录体验割裂 | P3 | 待评估 |
| PB-010 | 历史分析记录不可删除/重命名，无可标识「当前正在查看」的项，列表仅截断前 48 字 | 长期使用后历史堆积、难以管理；清理能力缺失 | P3 | 待评估 |
