# 开发复盘总结 · 提示词模板（AI 自查版）

> 用法：复制下面的提示词发送给 AI，它会自己去翻项目（git 历史、代码、文档、部署残留），找出卡点和主线，然后用**小白能听懂的话**写一份复盘报告。
> 你什么都不用讲，只需要把提示词发出去，等它把报告写完。

## 核心提示词

```
请自己动手调查这个项目，然后为我写一份开发复盘报告。
我不懂编程，请用我能听懂的大白话写，不要用专业术语；非用不可的术语要顺带解释一句。

【调查方法】请自行完成以下调查，不要问我：
1. 翻 git 提交历史（git log），看开发过程中发生了什么、有哪些反复和返工
2. 看项目里有哪些文件、哪些文档（需求文档、README 等），跟代码现状对照
3. 找开发过程中留下的"痕迹"：临时文件、废弃配置、没删干净的东西、注释里写的坑
4. 看代码里哪些地方明显是绕过去的、将就用的、没做完的

【报告要求】用大白话写，重点回答这些问题：
一、这个项目是怎么一步步做出来的（主线：先做了什么、后做了什么、中间改了什么主意）
二、开发过程中卡在哪了（卡了多久、为什么卡、最后怎么过的）
三、哪些地方做得不好（当时是怎么想的、造成了什么后果）
四、哪些地方没做完或埋着隐患（将来可能会炸的点）
五、下次做类似项目，建议先定好什么、避开什么（说人话，别写"加强安全意识"这种空话）

【语言要求】
- 整体语气像朋友聊天，不像官方报告
- 专业词第一次出现时，用一句大白话解释，比如"git 提交历史（相当于这个项目的修改日记）"
- 每条结论要说清楚"从哪看出来的"，但描述要简单
- 不要用表格，多用短句子和小标题

【输出方式】完成报告后，必须把它保存成本地 MD 文档：
1. 直接保存在项目的根目录（最外层文件夹）里，禁止新建任何子文件夹，文件名用"开发复盘与经验总结.md"（如果已存在，用"开发复盘与经验总结V2.md"这样递增的版本号，不要覆盖旧文件）
2. 存完后告诉我完整的文件路径，方便我去找
3. 不要把完整报告只写在对话里就不管了，对话里只需要简短说明保存位置和报告结构
```

## 如果报告还是看不懂

在报告下面追加一句：

```
我还是有点看不懂，请挑出最核心的 3 个问题，用更简单的话重新讲一遍，
每个问题用一句话说清楚"发生了什么、为什么、以后怎么避免"。
```

## 可选：控制报告长度

报告太长的话，在提示词最后加一句：

```
报告控制在 1000 字以内，只写最重要的事。
```

## 提醒

- 发送前确认当前目录就是项目文件夹（提示词开头写清楚项目路径也行）
- AI 翻 git 历史时如果提示项目不是 git 仓库，说明这个项目没做过版本记录，AI 会改成只从代码和文档里找线索，照样能写
