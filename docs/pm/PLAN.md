# AI 超级求职助手 — 当前产品与实施计划

> 权威状态日期：2026-08-21。本文只描述现役产品合同与未闭合事项；早期“无登录、无数据库、自定义任意模型地址”的方案已经退役。

## 1. 产品定位

面向求职者提供两条互补主线：

1. 上传 PDF 简历并粘贴岗位描述，由用户自带模型密钥（BYOK）生成岗位匹配分析、优化建议、求职信、10 道面试题和六维能力雷达图。
2. 从 PDF 或已有分析历史生成可编辑、可换主题、可发布分享的 HTML 在线简历/求职主页。

账号、简历、分析历史和在线简历草稿由 Supabase 持久化。用户密钥只参与单次请求，不持久化。

## 2. 现役范围

### 2.1 岗位匹配 1.0

- 用户必须登录后才能正式分析和保存历史。
- 浏览器解析可提取文字的 PDF；服务端保存私有原文件和结构化记录。
- JD 必填，服务端调用白名单中的 DeepSeek、通义千问、Kimi 或豆包接口。
- 用户填写模型名称和 API Key；默认 DeepSeek 模型名为 `deepseek-v4-flash`。
- 输出匹配度、分析说明、优化建议、求职信、10 道面试问答和六维雷达图。
- 最近 30 条分析历史持久化到 Supabase。

### 2.2 在线简历 2.0 MVP

- 创建来源：新上传 PDF，或本人一条已完成的历史分析。
- AI 将简历转成结构化内容，不生成任意 HTML，不虚构经历。
- 编辑内容：姓名、职业定位、简介、所在地、优势、经历、项目、教育、技能、联系方式和行动按钮。
- 编辑能力：自动保存、revision 乐观锁、模块排序/隐藏、增删条目。
- 主题：清爽专业、产品主页风、创意作品集风、企业科技风。
- 预览：编辑器内桌面/手机预览；公开页按响应式布局展示。
- 发布：用户自定义唯一 slug，并明确确认可公开内容。
- 公开页：`/r/{slug}`，未登录访客可以读取启用中的公开快照。
- 取消发布：将公开快照设为 inactive，公开链接立即不可访问，私有草稿保留。

### 2.3 会员与支付

- Waffo Pancake 测试环境提供月度/年度订阅收银台。
- 服务端验证 webhook 签名后，将事件写入 `billing_events` 并更新 `subscriptions`。
- `/api/membership` 返回当前套餐、会员状态、有效期与当期额度；只允许本人读取。
- 付款返回页等待 webhook 同步，以 Supabase 订阅状态为最终依据。
- AI 分析在调用模型前原子预留额度，失败则退回；套餐数值由 `plans` 表驱动。
- 分析额度按自然月重置：免费版 5 次，月度会员 300 次，年度会员 500 次。用户从免费版升级为付费套餐时，当期额度立即切换并从新套餐总额开始计数。

## 3. 用户流程

### 3.1 岗位匹配

1. 用户登录。
2. 上传不超过 10MB、可提取文字的 PDF。
3. 粘贴 JD，选择厂商，填写模型名称和 API Key。
4. 服务端校验登录态、输入和厂商白名单后调用模型。
5. 展示结果并保存私有简历、JD 和分析记录。

### 3.2 在线简历

1. 用户从首页进入 `/resume-sites/new`。
2. 拖入/选择 PDF，或登录后选择历史分析。
3. 选择主题，填写可选定位，输入本次 BYOK 配置。
4. AI 返回结构化内容，服务端创建私有草稿。
5. 用户在 `/resume-sites/{id}/edit` 编辑并自动保存。
6. 用户选择公开联系方式，填写 slug，并确认发布。
7. 服务端生成过滤后的公开快照；访客访问 `/r/{slug}`。
8. 用户可更新发布或取消发布。

## 4. 路由合同

| 路由 | 登录要求 | 用途 |
|---|---|---|
| `/` | 浏览无需登录；分析需登录 | 岗位匹配主界面和在线简历入口 |
| `/resume-sites` | 需要 | 管理本人在线简历 |
| `/resume-sites/new` | 可先准备材料；AI 生成前需要 | 选择来源、主题和 BYOK 配置 |
| `/resume-sites/{id}/edit` | 需要 | 编辑、预览、发布和取消发布 |
| `/r/{slug}` | 不需要 | 公开在线简历页 |
| `/api/resume-sites/**` | 除公开页读取外均需要 | 草稿、来源、生成和发布接口 |
| `/pricing` | 浏览无需登录；付款需要 | 选择套餐、查看会员状态与额度 |
| `/api/membership` | 需要 | 读取本人有效订阅和当期用量 |

生产环境的完整公开链接为 `https://<production-domain>/r/<slug>`。Vercel 只部署一次应用代码；每次简历发布是 Supabase 数据更新，不触发代码部署。

## 5. 数据与权限

### 5.1 私有数据

- `resumes`、`job_descriptions`、`analyses`：岗位匹配来源和结果。
- `resume_sites`：在线简历来源、私有草稿、主题、revision 和生成状态。
- 所有私有记录通过 RLS 按 `auth.uid() = user_id` 隔离。
- 简历 PDF 存放在 private Storage bucket，路径为 `{user_id}/{resume_id}/original.pdf`。

### 5.2 公开数据

- `resume_site_publications` 是与草稿分离的公开快照，不直接公开 `resume_sites`。
- 发布时运行 `normalizeContent` 和 `publicContent`；未勾选联系方式从公开 JSON 中删除。
- `anon` 只可读取 `is_active = true` 的公开快照。
- slug 全局唯一，仅允许 3–48 位小写字母、数字和连字符，并排除保留字。

## 6. 安全与隐私合同

- 禁止用户自定义模型请求 URL；服务端仅允许四家固定官方地址，防止 SSRF。
- `service_role`/secret key 不进入浏览器；前端只使用 Supabase publishable key。
- BYOK key 不写入数据库、日志、Cookie、本地存储、草稿或公开快照。
- 服务端独立校验登录态、资源归属、输入长度和文件边界。
- 页面只渲染 React 结构化内容；链接只接受 `http`、`https`、`mailto`、`tel`。
- 发布前默认隐藏联系方式，用户逐项选择并再次确认。

## 8. MVP 验收标准

1. PDF 拖放和点击选择都能解析，非 PDF、超过 10MB 或无文字文件得到明确提示。
2. 未登录用户准备的 PDF 文本和定位在登录回跳后仍保留，但不能绕过登录生成草稿。
3. 两种来源都能生成结构化草稿，API Key 不被持久化。
4. 草稿可编辑并自动保存；并发过期 revision 返回 409。
5. 四主题均可切换，桌面和手机预览无横向溢出或逐字竖排。
6. 发布必须具备姓名、职业定位和简介，并要求公开确认。
7. 未勾选联系方式不进入公开 JSON；非法或重复 slug 被拒绝。
8. 未登录访客能访问 active 的 `/r/{slug}`；无法访问私有草稿。
9. 更新发布替换同一站点的公开快照；取消发布后公开页立即 404。
10. Vercel 生产部署完成后，以生产域名完成一次真实发布生命周期验收。

长期回归用例统一维护在 `docs/qa/QA_CHECKLIST.md`。

## 9. MVP 之外

- 自定义域名、二维码、访问统计、密码保护和链接有效期。
- AI 局部改写、版本历史、草稿复制和多人协作。
- 图片/视频作品集、更多主题和主题自定义。
- SEO 分享图、站点地图、搜索引擎开关。
- 正式环境计费、自助取消/换套餐、发票、数据导出和账号永久删除。

这些能力不是当前交付范围，不应以“顺手补充”的方式混入本次发布。
